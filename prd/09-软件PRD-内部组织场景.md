## 1. 背景与定位

### 1.1 为什么加内部视角

现有全部需求与实现都围绕「员工 ↔ 客户」外部沟通。但一个组织里高频发生、同样"说完就消失在空气中"的还有四类**内部口头场景**：

| 场景 | 典型形态 | 现状痛点 |
|---|---|---|
| **会议** | 周会/项目会/评审/复盘 | 没人记纪要；定了的事没下文；争论过的问题两周后再争论一遍；没参会的人不知道结论 |
| **培训** | 技能培训/产品培训/新人带教 | 讲了什么没有沉淀，请假的人学不到；培训效果无检验；讲师内容随人走 |
| **讲座/分享** | 内部分享/外请讲师 | 1-2 小时长内容无人整理，听时激动、听完全忘 |
| **管理谈话**（含训话） | 一对一面谈/批评指导/绩效沟通 | 双方口头承诺（改进项/资源支持）无记录，事后各说各话；HR 过程无留痕 |

### 1.2 "自己是自己的客户"的三重价值（本册立项理由）

1. **真实数据飞轮，成本最低**：内部会议/培训是零客户协调、零告知门槛、每日发生的场景——当前唯一瓶颈是"缺少真实数据验证分析质量"，内部场景直接补上。
2. **压测产品硬能力**：内部会议是 4-8 人、60-120 分钟长录音，比销售 1v1 难度高一个量级——说话人分离上限、长音频转写成本、长文本分析质量，全在这里真实压测。
3. **对外销售的实证背书**：客户问"你们自己用吗"，答案是用自己公司的真实会议纪要/培训知识库演示（脱敏）；内部场景打磨出的模板与敏感场景合规处理，直接打包为对外的「组织场景」能力。

### 1.3 边界（不覆盖）

- **线上会议**（腾讯会议/Zoom）不接入——工牌管线下物理现场，线上会议用各自自带转写，不重复造；
- 不做新硬件、不改固件（1.75C 现有固件 v2.5.7 零改动；会议室部署=插电常驻）；
- 不做考勤/门禁联动（05 册已有通道，本册不碰）。

## 2. 核心设计决策

| # | 决策 | 理由 | 放弃的选项 |
|---|---|---|---|
| K1 | **同一管线，场景模板化**：录音→转写→分离全部复用，只在 LLM 分析层按「场景模板」路由 prompt 与输出结构 | analysis.js 已验证「配置注入+JSON 约束+原文可溯源」架构，换 system prompt 即换场景，改造成本约 1 天 | 为内部场景另建独立管线/表（重复建设，权限与合规逻辑双份维护） |
| K2 | **四场景归并为三个模板**：会议（meeting）/ 培训·讲座（training，讲座=单向培训，参数化）/ 管理谈话（talk） | 讲座与培训的输出物重叠度 >80%，分开无增益 | 讲座独立模板（真出现需求再加，配置域可扩展） |
| K3 | **场景判定一期纯手动+按设备默认**：记录入库后可标场景并重分析；设备可配默认场景（会议室设备=meeting） | 现链路由 VAD 自动收口、无"发起"动作，自动场景识别误标代价高；手动标注+重分析是已验证能力 | LLM 自动识别场景（P2 再评估，先攒人工标注数据） |
| K4 | **管理谈话做"对称透明"而非单方监控**：被谈话人可查看自己名下的谈话记录，权限默认仅谈话双方+admin | 训话是全产品最敏感场景；对称透明把"监控感"转化为"双方承诺都有记录、对员工也是保护"（与对客户讲的服务争议逻辑同构） | 管理者单方可见（合规与员工信任双输，07 册员工数据边界不容） |
| K5 | **AI 不给"人"贴标签**：谈话场景不做情绪/态度/忠诚度评分，只提取事实层（双方承诺/争议点/结论） | AI 给人定性是红线（07 册原则"AI 负责整理分析、人负责判断"）；评估人留给管理者 | 情绪曲线/态度打分（竞品有类似功能，明确不做并作为对外差异化表态） |
| K6 | **长会聚合依赖会话模式落地**：会议场景必须用累积/手动收口（会话模式设计文档 §2），否则 VAD 碎片化导致一天几十条碎片+几十次 LLM 分析 | 该文档已给出完整实施清单（~1.5 天），且结论"不改变设备行为、不新增功耗要求" | 接受碎片化先跑（分析成本爆炸，纪要不可用） |

## 4. 三模板报告结构（analysis.js 输出分型）

均强制：每条结论带原文引用、`meta.ai_generated=true`、过 redact 双层脱敏（现有硬规则不变）。

### 4.1 会议模板 meeting（输出：纪要）

| 模块 | 内容 | 对应现有概念 |
|---|---|---|
| summary | 会议概要（议题→结论结构，3-5 句） | ANA-01 |
| topics | 分议题摘要：[{topic, conclusion, discussion}] | ANA-02 分段摘要 |
| decisions | 决议：[{what, owner, evidence}]（定了什么、谁负责） | 新增 |
| action_items | 行动项：[{what, owner, due}]（含会上承诺的资源/支持） | ANA-10 todos 升级 |
| disputes | 争议点：[{topic, side_a, side_b, status}]（分歧与当前状态） | 新增 |
| open_issues | 未决事项（下次会议回顾的钩子） | 新增 |
| attendees_hint | 说话人分离出的发言人数（参会人确认由人工完成） | REC-13 |

### 4.2 培训/讲座模板 training（输出：知识）

| 模块 | 内容 |
|---|---|
| summary | 讲了什么（主题/受众/主线） |
| knowledge_points | 知识点列表：[{point, detail, evidence}]（结构化入知识库） |
| qa | 答疑整理：[{q, a}]（提问环节实录整理） |
| quotes | 金句/关键表述（案例库素材） |
| quiz | 考核题建议：3-5 题（培训效果检验，出题依据带原文） |
| chapters | 长内容时间轴章节（>45min 内容分段，衔接 REC-05 分段总结） |

### 4.3 管理谈话模板 talk（输出：双向纪要）

| 模块 | 内容 |
|---|---|
| summary | 谈话概要（中性事实表述，禁评价性措辞） |
| commitments | 双向承诺：[{by: 管理者\|员工, what, due, evidence}]（核心输出：员工改进项+管理者资源承诺并列） |
| issues_discussed | 讨论过的问题清单（事实层） |
| unresolved | 未达成一致的点 |
| next_review | 建议回顾时点与回顾内容（下次谈话前自动带出本次承诺完成情况） |

**显式不做**（K5 红线）：情绪评分、态度打分、忠诚度/离职倾向推断。

| 类别 | 需求 |

## 7. 验收标准

1. **纪要质量**：一场 ≥60min、≥4 人真实会议，decisions/action_items 每条带原文引用，人工评"无编造、归属正确"；争议点不遗漏重大分歧。
2. **改标重分析**：同一记录 sales→meeting 切换后报告结构随模板变化，旧报告可回看（INT-11）。
3. **Ask AI 内部问答**："上次周会关于 X 定了什么"返回带来源编号的决议原文（零改造验证）。
4. **权限**：无关 manager 账号访问 talk 记录 403；被谈话人本人访问 200 且留审计（INT-40）。
5. **收口**（依赖 INT-02 落地）：2h 会议（含 ≥2 次中途休息）产出 1 条聚合记录、1 次分析，而非 VAD 碎片。
6. **红红线**：talk 模板对含明显情绪化对话的样本，输出不含情绪/态度评分字段（测试样本断言）。

## 8. 技术风险（先实测再拍板默认值）

| 风险 | 说明 | 对策 |
|---|---|---|
| 会议室远场收音 | 1.75C 双麦阵列为近场设计，3-5m 远场信噪比未验证 | INT-03 实测：桌面中央 2m/3m/5m 三档转写字错率对比；不达标→主讲佩戴（INT-03 降级路径）或后续加指向麦（硬件二期，本册不立项） |
| 分离上限 6 人 | 讯飞转写大模型说话人数上限 | 一期只服务 ≤6 人会议；超额场景纪要降级为"不区分发言人" |
| 长文本分析质量 | 2h 转写 2-3 万字超单次 prompt 舒适区 | 先实测 DeepSeek 长文本纪要质量；不达标再上"分段总结→汇总"两级管道（REC-05 机制复用） |
| VAD 碎片化 | 未落会话模式前会议场景不可用 | 实施顺序强约束：INT-02 先行（文档已给 ~1.5 天清单），模板可先行用短会/分段验证 |
