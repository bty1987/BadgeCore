## 2. 关键指标（P0 验收线）

| 能力 | 指标 | 目标 | 评测方法 |
|---|---|---|---|
| AI-01 ASR | 字错率 CER | 安静 ≤5% / 噪声 65dB ≤8%（普通话） | 标注测试集 50h（门店/展厅/办公室三场景） |
| AI-01 ASR | 首字延迟 | ≤ 800ms；实时率 RTF ≤ 0.3 | 供应商压测报告 + 自测 |
| AI-03 分离 | 说话人分离准确率 | 2 人 ≥ 95% / 3 人以上 ≥ 90% | DER ≤ 0.10（pyannote 协议） |
| AI-04 总结 | 摘要事实一致性 | 人工评分 ≥ 4.2/5；关键信息零幻觉 | 200 条双盲评测 |
| AI-05 分析 | 立场/竞品抽取 F1 | ≥ 0.85（竞品词典内）/ ≥ 0.75（词典外） | 标注集 300 场沟通 |
| AI-05 意向度 | 与成交结果相关性 | 试点期 AUC ≥ 0.75（分高者更易成交） | 试点 3 个月回溯 |
| AI-06 违规 | 检出率 / 误报率 | ≥ 90% / ≤ 5% | 对抗测试集（含 20% 易混淆正常话术，如正常催签 vs 诱导仓促签约 ★ 对标 SaleSmart 判定说明设计） |
| AI-08 Ask AI | 答案可溯源率 | 100% 答案带数据/原文引用；越权问题拒答 | 红线测试 |

## 3. 技术方案要点

### 3.1 ASR 抽象层（AI-01/02）

```
音频流 → 统一接入层(分帧/鉴权/计量) → 供应商适配器(讯飞|阿里|火山)
     → 转写规范化(时间戳/ITN/标点) → 说话人分离 → 下游分析队列
```
- 双供应商按企业配置路由（04 册 ADM-207）；故障自动切换（30s 内）。
- 热词：企业级热词库（≤2000 词）下发供应商定制接口；每沟通附加环节级热词（如竞品名）。

### 3.2 LLM 分析管道（AI-04/05/06/07）

- 输入：转写文本（带说话人/时间戳/环节标注）+ 企业配置（成交模型检查项/违规项定义+典型话术+非违规判定说明/竞品词典/总结模板）。
- 输出：JSON Schema 强约束（立场条目必须带原文引用区间，供 ANA-03 跳转）。
- 成本控制：长文本按环节分段 map-reduce；违规检测先规则预筛（关键词/静音段/时间段）再 LLM 判活，降低 70% 调用量（预估）。
- 模型部署：一期公有云 API（数据脱敏与协议约束，07 册）+ 二期私有化/开源模型（Qwen 系）双轨评审。

### 3.3 RAG 与 Ask AI（AI-08/11）

- 知识源：知识库文档、历史沟通报告、案例库；统一向量库，按企业/数据范围分 namespace。
- 权限前置：检索前先解析提问者数据范围（04 册 ADM-313），越权内容不进上下文。
- 双视角：SalesCoach（销售视角：话术/待办/客户）与 SalesCommander（管理视角：团队/趋势/风险）（★ 对标 SaleSmart 双助手命名体系）。
- 定时任务：自然语言描述 → AI 解析时间范围与指标 → 生成报告 → 站内信/企微推送（★ 对标 SaleSmart「定时任务收件人=销售本人」机制）。

### 3.4 实时辅助（AI-09）

- 一期（规则触发，延迟 < 500ms）：客户提及竞品名 → 推送竞品应对卡；检测到异议关键词 → 推送 FAQ 卡；风险词（如「私下」「回扣」）→ 管理者实时告警。
- 二期（LLM 流式）：转写流实时输入小模型，生成下一句话术建议；延迟目标 < 2s。

## 4. 评测与数据集建设

1. **测试集**：启动期建设 50h 标注音频 + 300 场标注沟通（多行业：家装/汽车/医美/门店），含对抗样本（诱导话术 vs 正常催签）。
2. **回溯评测**：每月全量抽样 1% 沟通人工复核，指标看板（CER/DER/F1/违规误报）向产品周会汇报。
3. **badcase 闭环**：App 端报告页「反馈不准」入口 → 自动归集原文+配置快照 → 周度标注回流。

## 5. 开放问题

1. LLM 供应商终选（性能 vs 数据合规 vs 成本），建议 POC 三家并行，用 §2 指标实测。
2. 私有化部署的最小算力规格与成本（影响 M3 后企业私有化交付报价）——本地 whisper/funasr 路线为此技术储备。
3. 方言 ASR 一期覆盖哪几个省（按试点企业地域定）。
