## 1. 背景与机会

### 1.1 业务痛点

| 角色 | 痛点 | 现状 |
|---|---|---|
| 一线销售/客户接待 | 沟通质量靠个人悟性，销冠经验无法复制 | 无沉淀工具 |
| 销售管理者 | 线下沟通过程不可见，只能听汇报/看结果 | 抽查陪访成本高 |
| 员工 | 工牌仅为身份载体（胸卡/PVC卡），打卡、门禁、访客登记分散在多个系统 | 多系统割裂 |
| 公司 | 客户沟通数据零资产化；服务合规（承诺/夸大/私单）无抓手 | 风险敞口 |

### 1.2 市场验证

- 赛道已被验证：讯飞、中关村科金、钉钉、明略、云知声均有成熟「AI 录音工牌」产品，硬件价格带 999 元起，按「硬件 + SaaS 订阅」计费。
- 对标产品 SaleSmart（云学堂）实现了「工牌录音 → 实时转写 → AI 分析 → 赋能 → 管理洞察」完整闭环，本产品以其功能面为质量基线（见 08 册）。
- 市场空白：现有玩家全部聚焦「销售录音分析」单场景，**没有厂商做「全员数字工牌」**（身份 + 考勤 + 门禁 + 通知 + 销售/服务赋能一体）。

### 1.3 我方机会

1. **全员覆盖**：工牌人人佩戴 → 采买决策从「销售部门工具」升级为「公司基础设施」，客单价与粘性更高。
2. **一牌多能**：身份展示、考勤、门禁、通知、销售赋能合并，替代多套设备（PVC 工卡 + 考勤机 + 录音工牌）。
3. **数据闭环**：全员行为数据（考勤/动线）+ 沟通数据（销售/服务）在同一平台，管理洞察维度更全。

## 2. 产品定位

> **一句话**：面向企业全员佩戴的软硬一体数字工牌 —— 对全员是「身份 + 考勤 + 门禁 + 通知」的智能终端，对销售/服务团队是「AI 沟通赋能」的生产力工具。

### 2.1 产品原则

1. **一个平台，两种模式**：全员模式（低功耗待机：身份/考勤/门禁/通知）与业务模式（工牌激活录音/定位等高功耗能力，按角色授权）。
2. **录音必须合规前置**（见 07 册）：不告知不录音、员工客户双告知、离职/拒录即停。
3. **对标 SaleSmart 质量基线**：其已验证的功能面（沟通配置九大域、违规语义检测、Ask AI 等）为本产品 P0/P1 的功能清单来源。
4. **硬件全自研**：从芯片方案自主设计，保证 BOM 成本、固件 OTA、数据安全的完全可控（见 02 册）。

### 2.2 范围边界（一期不做）

- 不做 CRM 全模块（线索/商机管理仅做基础版 + 标准 API 对接外部 CRM）
- 不做 4G 蜂窝版（一期蓝牙桥接手机 App；4G 版列入硬件二期）
- 不做 OpenAPI 之外的第三方应用市场

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 员工（全员） | 佩戴工牌的所有员工 | 兼职化繁为简：一牌通行、少装 App |
| 销售/顾问 | 有授权启用录音的角色 | 沟通有复盘、话术有辅导、签单有提升 |
| 销售管理者 | 团队 leader | 过程可见、风险可查、团队效能可量化 |
| HR/行政 | 工牌/考勤/门禁管理员 | 发卡销卡、考勤门禁一体化管理 |
| 企业超管 | 平台管理员 | 配置、权限、数据安全、审计 |
| 客户（间接受影响方） | 与员工沟通的外部人员 | 知情权、隐私不被滥用（07 册） |

### 3.2 核心场景（一期）

**S1 全员日常**：员工佩戴工牌到岗 → BLE 自动考勤 → 刷牌/NFC 过门禁 → 工牌墨水屏显示姓名/部门/访客二维码 → 下班自动签退。
**S2 销售沟通**：销售在手机 App 点击「立即录制」（或按工牌物理键）→ 工牌拾音经蓝牙实时传 App → App 经 WebSocket 流式上传云端 ASR → 沟通结束生成转写+AI 报告。
**S3 会后复盘**：销售查看报告（摘要/客户立场/竞品/意向度/待办），系统推送待办与跟进计划，销冠话术沉淀案例库。
**S4 管理洞察**：管理者在指挥舱看实时沟通看板、团队排行、违规分布；收到风险预警（沉默客户/立场反对/竞品提及）。
**S5 即时辅导**：沟通中实时辅助按规则推送话术提示；新人在学习中心学习知识库与金牌话术。
**S6 合规质检**：违规模型自动扫描全部沟通，命中项定位到原文片段，管理者处置并留痕。

## 4. 产品架构

### 4.1 系统组成

```
┌────────────────────────────────────────────────────┐
│                    应用层（多端）                     │
│  员工App(伴生App)  管理Web后台  指挥舱(团队端)  HR/行政端  │
└───────────────┬────────────────────────────────────┘
                │ HTTPS / WSS
┌───────────────┴────────────────────────────────────┐
│                    平台服务层                        │
│  账号/组织/权限  设备管理  录音/转写管道  AI分析服务      │
│  沟通配置引擎(模型/流程/违规)  全员服务(考勤/门禁/通知)   │
│  数据洞察  开放平台API  审计日志                       │
└───────────────┬────────────────────────────────────┘
                │ TLS + 设备双向认证
┌───────────────┴────────────────────────────────────┐
│                  终端层（自研硬件）                    │
│  数字工牌终端：MEMS麦阵/BLE/WiFi/NFC/墨水屏/按键/震动    │
│  伴生App：蓝牙桥接、录音上传、状态监测                   │
└────────────────────────────────────────────────────┘
```

### 4.2 关键数据流（录音链路）

```
工牌拾音(4麦阵列+前端降噪) → BLE传输 → 伴生App(缓存+断点续传)
→ WSS流式上传 → 云端ASR(热词/方言) → 转写文本
→ 说话人分离标注 → LLM分析管道(摘要/立场/竞品/意向/违规/任务达成)
→ 报告与画像沉淀 → 看板/预警/案例库/CRM同步
```

> 对标实证：SaleSmart 采用同构链路（BLE 工牌 → App → wss://…/ws → 云端 ASR），其「10 分钟+500 字自动分段总结」「离线自动补传」「设备级录制互斥」为已验证的工程细节，本产品 1:1 采纳为需求（REC-08/09/12，见 03 册）。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 录音合规纠纷 | 高 | 07 册合规专册前置评审；双告知交互硬约束（不告知无法录制） |
| 自研硬件进度/良率 | 高 | 02 册 EVT/DVT 双闸门；同步备选 ODM 方案做保底（不并轨量产） |
| ASR 方案依赖外部 | 中 | 双供应商（讯飞/阿里/火山）抽象层，热词与私有化可切换（06 册） |
| 员工抵触（被监控感） | 中 | 数据权限最小化：录音数据默认仅本人+授权管理者； HR 考勤与沟通数据隔离存储 |
| 成本超预算 | 中 | BOM 目标价与 DFX 在 EVT 前锁定（02 册 §8） |
