# BadgeCore Web 控制台 · 改版设计 Spec（三方向共同输入）

## 项目是什么
BadgeCore 员工数字工牌的 Web 控制台——内部 B2B 工具，单一产品里有两个工作区：

1. **销售工作台**（销售每天用）：首页（问候/统计/今日日程/待办/情报中心）、沟通列表（表格+筛选+上传录音）、沟通详情、客户、案例库、沟通计划
2. **管理后台**（管理者/管理员配置用）：沟通配置 9 域（信息收集/成交模型/任务模型/能力模型/沟通总结/沟通分析/沟通流程/违规检测/竞争对手）、客户管理与画像、洞察配置、风险预警、知识库、案例库、数据看板、设备接入、考勤、组织架构/员工名册/角色权限、全局配置、Ask AI

## 受众与场景
- 销售员：每天多次打开，看自己的沟通记录、待办、客户；桌面为主；要快、不费眼、路径短
- 管理者/管理员：低频但长时段配置；表格表单密度高；要找得到、不迷路
- 内部工具，用户量小，但主理人要求「体面、不像临时凑的」

## 核心信息（页面要说的事）
- 销售端：今天该做什么（日程/待办）、沟通过多少（统计）、哪些客户有风险（情报）
- 管理端：配置体系全貌（9 域+组织+设备）、数据现状（看板）

## 情感基调
专业、克制、可信赖；高效不等于冷冰冰；是中国团队每天用的工具，中文排印要舒服

## 本次改版的两个硬需求
1. **页面样式布局整体优化**：现状是「圆润精修 v2」（对标某竞品截图 1:1 抄的），主理人认为不够好，要更有设计品味的整体方案
2. **销售/管理切换方式调整（重点）**：
   - 现状问题：管理端顶栏有「销售助手/我的企业」两个 pill tab；销售端却**没有任何显式切换入口**，只能点左下角 36px 小头像盲跳 /settings.html；两套壳（窄图标栏 vs 顶栏+分组侧栏）完全不同构，切换后空间坐标全变
   - 要求：切换入口**两侧一致、位置固定、显式可预期**；切换后不迷路；保留键盘可达性更好

## 输出格式与尺寸（三版必须统一）
- 单文件 HTML 交互原型，零依赖（不用框架/CDN 字体可用系统栈），1440×900 为主视口
- 每版必须同时演示：销售工作台一屏（含真实菜单：首页/沟通/客户/案例库/看板）+ 管理后台一屏（含真实分组菜单）+ **可在两屏间真实点击切换**
- 真实内容：菜单名、页面标题、统计卡、表格列一律用上面的真实业务词，不造 lorem
- 可读性底线：正文 ≥14px、标签 ≥12px、可点元素 ≥44×44px 热区、正文对比度 ≥4.5:1；至少不破 375 宽（可横向滚动兜底）

## 已知约束
- 最终要落回现有技术栈：`server/public/assets/badge-ui.css`（CSS 变量 token 体系）+ `server/public/assets/app.js`（零依赖，icon() 内联 SVG 线性图标库），纯静态多页
- 中文为主，字体只能用系统栈或 Google Fonts（交付到生产时最好系统栈）
- 现有主色 #436bff / 渐变 #436bff→#5c1eff 只是「现状」，不是品牌约束——可以换，但要给出理由
- 数据表格是核心形态：表格密度、筛选行、分页、pill 标签体系要设计到位

## 素材
无图片素材需求，纯 UI/版式设计；logo 现状是渐变圆角方块（无字），可沿用/重设计

## 现状诊断摘要（已亲眼核实，来自 7 张基线截图）
销售端：问候条弱、引言条突兀、统计卡平庸、空态用 emoji、左下角头像孤立且是隐藏的管理端入口、卡片圆角+浅阴影均匀铺陈无重点、层级靠字重硬撑
管理端：顶栏与侧栏视觉无分隔、侧栏分组标题与菜单项层级弱（13px vs 13.5px 几乎无差）、菜单重复项多（字段设置出现两次、案例库两处）、表格密度偏松、pill 切换「销售助手/我的企业」命名与品牌「管理后台」不一致、无快捷搜索
两壳不同构 = 切换后空间记忆清零
