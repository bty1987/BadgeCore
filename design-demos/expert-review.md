## 一、专家评审（现状）

按严重度从高到低排序，共 12 条。

**1.（P0）销售端没有任何显式的管理端切换入口**
问题：销售端唯一的「逃生口」是左下角 36px 圆形头像，点击盲跳 /settings.html；无文字、无 tooltip 说明、无菜单。
为什么是问题：一个双工作区产品，一半用户不知道另一半存在；头像的通用语义是「账户/个人设置」，不是「切换工作区」，属于语义错位 + 可发现性为零的双重缺陷。
修法方向：显式、固定、两侧同位的切换控件（见第二部分推荐方案），头像回归账户语义。

**2.（P0）两套壳完全不同构，切换即空间记忆清零**
问题：销售端是 72px 窄图标栏（`appbar`），管理端是 56px 顶栏 + 208px 分组侧栏（`topbar`+`sidebar`）；主区内边距也不同（22/26 vs 24/28）。
为什么是问题：切换后 logo 位置、导航方位、菜单密度、内容起点全部改变，用户每切一次都要重建空间坐标系；对「低频但长时段」的管理者尤其致命——他们同时是两个端的最重度切换者。
修法方向：单一壳，或至少顶栏/侧栏框架完全同构，只换菜单内容。

**3.（P0）工作区命名三套说法互相打架**
问题：管理端顶栏 tab 叫「销售助手 / 我的企业」，顶栏品牌位又叫「管理后台」；「我的企业」组下装的其实主要是 9 个沟通配置域，与企业本身无关。
为什么是问题：命名是导航的原材料。三个名字指向同一套东西的不同切面，用户无法建立「我在哪、能去哪」的心智地图。
修法方向：全局统一为「销售工作台 / 管理后台」两个工作区名；「我的企业」组降级改名为「组织与人员」。

**4.（P1）侧栏层级系统失效，顶栏侧栏无分隔**
问题：管理侧栏组标题 13px/600 与菜单项 13.5px/500 几乎无差（仅差 0.5px）；顶栏与侧栏同为纯白，仅靠 4% 透明度发丝线相接，品牌、tab、搜索区糊成一条。
为什么是问题：分组侧栏的全部价值就在「组」的可扫读性上，层级失效等于 23 个菜单项平铺成一长串；顶栏侧栏无分隔则让横向纵向两套导航争夺同一块视觉区域。
修法方向：组标题 12px、加强字距与灰度（--text-3）、去掉组图标或缩至 12px；菜单项 14px；顶栏给独立底色或 8% 灰界线，或干脆合并成一条壳。

**5.（P1）表格密度偏松，与「配置密集型」内容不匹配**
问题：td padding 13px 16px、字号 13.5px，信息收集/违规检测这类几十行的配置表一屏只能看 12 行左右。
为什么是问题：管理端的核心动作是「扫一眼全量条目找某一条」，密度直接决定效率；现在每行都在为「呼吸感」付费，但呼吸感应该来自留白分区，不是每一行单元格。
修法方向：默认密度行高约 40px（垂直 padding 10px），提供「紧凑」档；单元格字号 13px，说明性正文保持 14px。

**6.（P1）菜单 IA 有重复项**
问题：「字段设置」出现两次（沟通计划组与客户管理组，指向完全相同的 /config.html?domain=info_fields）；案例库在销售端与管理端各有一份入口且无任何区分标识。
为什么是问题：重复入口让用户怀疑「这两处是不是不同」，也激活态互相打架（同一个 active key 两处同时亮）。
修法方向：合并同 URL 项；跨工作区共享实体（案例库）在次侧入口加「销售端共用」副文本或直接只保留一处。

**7.（P1）空态与列表用 emoji 表达图标语义**
问题：首页用 ☀️ 🕑 ☑️ ⚠️ 📡 🗓️，空态也依赖 emoji。
为什么是问题：emoji 跨平台渲染不可控（Win/Mac 形态差异大）、无法随主题换色、无法控制粗细，与全站精心维护的 24px 线性 SVG 图标库（icon()）并存时风格割裂；内部 B2B 场景里 emoji 传递「临时凑的」气质，正是主理人明确不要的。
修法方向：一律换用现有 icon() 线性图标，空态统一「淡底圆形 + 线性图标 + 一句引导文案 +（可选）一个次级动作」。

**8.（P1）可访问性存在多处硬伤**
问题：a) tag 彩色对（如 #52c41a/#f6ffed、#fa8c16/#fff7e6）对比度约 2:1–2.5:1，远低于 4.5:1；b) 按钮/链接/导航无 :focus-visible 样式，键盘用户只有输入框有焦点环；c) 侧栏激活态仅靠 #f0f6ff 浅底标识，与白底非文本对比 <1.1:1；d) 销售端导航文字 11.5px，低于 12px 底线。
为什么是问题：这是每天使用的生产工具，键盘可达与色彩可辨是底线不是加分项；spec 也明确要求正文 ≥14px、标签 ≥12px。
修法方向：tag 前景色统一加深一档（用深色文字 + 淡底）；全站补 :focus-visible 2px 焦点环；激活态加左侧 3px 主色条作为冗余编码；导航文字回到 12px 以上。

**9.（P1）中文排印细节粗糙**
问题：a) 品牌字「管理后台」加 letter-spacing .5px——中文靠字重与字号分层级，正字距是西文小号大写标题的习惯；b) 统计数字、表格时间列未启用等宽数字（tabular-nums），数字跳动；c) 中文正文行高未显式声明，继承默认值。
为什么是问题：中文排印舒服是 spec 的明确基调要求；数字是这产品最高频的信息形态（沟通次数、时长、条目数），跳动会持续产生廉价感。
修法方向：中文默认 letter-spacing: 0（仅英文标签可用字距）；数字列统一 font-variant-numeric: tabular-nums；正文行高 1.6、表格 1.5。

**10.（P2）卡片与阴影系统无层级，装饰预算超支**
问题：所有卡片同 12px 圆角 + 同款阴影 + hover 上浮；不可交互的静态卡也做 hover 抬升与渐变顶条；圆角标度混乱（18/12/10/9/8 混用）；主按钮渐变、logo 光晕、顶栏毛玻璃、统计卡渐变条同时在场。
为什么是问题：当一切都浮起来，就没有东西是重要的；hover 反馈用在不可点元素上是「假可供性」，会训练用户不敢信任 hover。装饰元素叠加后互相稀释，「体面」变成「热闹」。
修法方向：建立三级圆角标度（如 4/8/12）并限定用途；hover 效果只给可点元素；阴影收敛为一档，分区主要靠描边与底色；渐变只保留 logo 一处。

**11.（P2）销售首页首屏三连弱：问候弱、引言突兀、统计无主次**
问题：问候条是一张普通卡里的一行 17px 文字 + emoji 太阳；引言条是渐变底 + 靛蓝文字，与全站蓝系冲突；四张统计卡同尺寸同字重平铺，没有「今天最重要的数字」。
为什么是问题：首页是每天打开的第一屏，现在既没有仪式感（士气）也没有信息重心（今天该做什么）；引言条用了与主色冲突的靛蓝渐变，是全站唯一一处紫色系，孤立突兀。
修法方向：首屏做一个明确的「今日区」：大号日期/问候 + 最大号的一个数字（今日待办）；引言降级为待办区底部的一行弱文案或干脆移除；统计卡分主次（一张主卡 + 三张次卡）。

**12.（P2）数字与状态的信息形态未设计**
问题：表格里的时间、数量、状态 pill 均为同字号同灰度文本；风险关键词以彩色 tag 内联在句子里，行高被撑乱。
为什么是问题：B2B 表格的扫读效率依赖「列内同形态」——每列的值应当有统一的视觉形态与宽度节奏，现在每行自己长自己的。
修法方向：时间列统一等宽 + --text-3；数量列右对齐；内联多 tag 改为「关键词， 关键词」纯文本 + 数量徽标，点开看详情。

## 二、切换方式设计方案（本次硬需求）

### 推荐：方案 A+（单一壳 + 侧栏顶部工作区切换器）

三个候选中 A 是唯一同时满足「两侧一致、位置固定、显式可预期、切换不迷路」的形态，B 次之，C 不推荐。

**控件形态（具体规格）**
- 位置：左栏第一格，纵向固定不随菜单滚动（sticky），两侧完全同位
- 尺寸：高 44px，宽 = 侧栏宽 − 24px（两侧栏宽统一 224px）
- 内容：20px 圆角方工作区图标（销售端 mic/工牌图标、管理端 shield 图标，浅底 chip 形）+ 工作区名 14px/600 + 右侧 12px 下 chevron
- 下拉浮层：宽 280px，两个选项，每项 = 图标 + 名称（14px/600）+ 一行 12px 描述（销售工作台「我的沟通、客户与今日待办」；管理后台「九域配置、组织与数据看板」）+ 当前项 check 图标；底部显示各工作区「上次访问页」副文本
- 键盘可达：按钮 aria-haspopup="menu" + aria-expanded；下拉内上下方向键、Enter 确认、Esc 关闭；全局快捷键 Ctrl/Cmd+Shift+S 直接翻转工作区
- 落点策略：切到销售端 → /index.html；切到管理端 → localStorage 记住的上次管理页（默认 /dashboard.html）。URL 结构不动，切换器只是带记忆的链接。

**两侧同构到什么程度**
壳的框架 100% 同构：同侧栏宽、同切换器、同底部账户区、同（可选的）48px 全局工具条（搜索/通知/头像）。唯一不同 = 侧栏菜单内容与主题 accent 的微调。切换动画只发生在菜单区，切换器本身纹丝不动——它就是用户的空间锚点。

**信息量差异的处理（5 项 vs 9 组约 23 项）**
- 行规统一：两侧菜单项同为 32px 行高、同激活态样式（浅底 + 左 3px 主色条），保证「切换后手感不变」
- 销售侧 5 项偏空：菜单下方加常驻区——「今日待办」迷你摘要（3 条，可点）与 Ask AI 入口，让 224px 栏有稳定视觉重量，而不是靠拉大间距填空
- 管理侧 9 组偏重：组标题 12px/--text-3，组间 8px 间距；侧栏独立滚动，切换器吸顶；把 Ask AI、全局配置这类低频组排在最底
- 命名规范随架构落地：工作区 = 销售工作台 / 管理后台；管理侧栏原「我的企业」组改名「组织与人员」；「销售助手」「我的企业」作为工作区名全部废除

**为什么不选 B（双壳同构 + 顶栏分段控件）**
分段控件本身是好控件，但它要求销售端也养一条常驻顶栏——现状销售端没有顶栏，等于仍要新建半套壳；且分段控件在顶栏、菜单在侧栏，切换后用户视线要在两个纵向位置之间跳。B 是方案 A 的可接受降级（若团队坚持保留「管理后台要有顶栏品牌位」），仅此而已。

**为什么不选 C（账户菜单内切换）**
两条硬伤：语义错误（切换工作区是导航行为，不是账户行为，藏在头像里等于延续现状的语义错位）；可发现性没有改善（仍是二级点击后才见）。C 只适合作为 A 的补充——下拉浮层底部顺带放「退出登录」，头像回归账户菜单本职。

## 三、六张方向卡

### C1 · 佐藤可士和——「一枚徽章，说了算」（最佳设计师 × 能量派）

- **逻辑来源**：最佳设计师。借佐藤可士和的两条具体规则：其一，UNIQLO 再造的「极致减法 + 单一强符号」——把信息整理到只剩必要，然后让一个符号贯穿全局；其二，麒麟午後红茶式的「单品一色主义」——用一种颜色的纯度承载全部情绪，不靠色彩数量。能量感来自符号的重复与纪律，而非装饰堆叠，正好适配「表格是主体」的现实约束。
- **借的是什么**：全站唯一形状记号 = 24px 圆角方 chip（radius 6px），logo、导航图标容器、状态点、空态插画单元全部同形；色彩配给 90% 灰白 + 10% 单一暖色，暖色只绑定「今天/行动/进行中」一个语义；8px 基准网格，问候大字与统计数字同基线对齐；字重跳档（中文 Bold 标题 vs Regular 正文）替代字号碎档。
- **主角素材**：巨大的「今日数字」——今日待办/今日沟通做成 48px Bold 等宽数字 + 徽章 chip 状态点，首屏像一台打卡机，给销售「今日份士气」的仪式感。
- **骨架**：单一壳，左 232px 白侧栏，第一格即徽章形工作区切换器（chip 图标 + 工作区名 + chevron，下拉同 C 选项规格），下方销售 5 项 / 管理 9 组原地替换。
- **胆量花在哪**：全站只允许出现一个彩色——暖朱红，且只准出现在「今天要做的事」上（今日待办数字、日程此刻线、发起沟通主按钮）；蓝降级为链接色。
- **form 来自内容的哪里**：徽章 chip 就是「员工数字工牌」本身——产品名 BadgeCore 的最小图形化身，天然长在内容里。
- **token 提案**：#E8432D（行动朱红）/ #1F2329（墨）/ #5A6072（次级）/ #9AA0AE（弱）/ #F2F3F5（页底）/ #FFFFFF（面）/ #2F6BFF（链接蓝，仅链接与图表辅助）；radius 6/10；阴影一档 0 1px 2px rgba(31,35,41,.06)；字号阶梯 12/13.5/14/16/20/28/48；字体栈 "MiSans","PingFang SC","Microsoft YaHei" + tabular-nums。

### C2 · Irma Boom——「九域即九章」（最佳设计师 × 克制派）

- **逻辑来源**：最佳设计师。Irma Boom（Irma Boom Office）的书籍信息设计方法：目录即界面、编号即导航、小字号精确排印、纸白与墨色的大面积留白。BadgeCore 管理后台的 9 个沟通配置域天然是一本书的九章——成交模型、能力模型、沟通流程……直接把侧栏做成带编号的索引，配置工作被译成「编纂一本手册」。
- **借的是什么**：编号系统——每个域前缀等宽数字 01–09（12px tabular，#A8A79E），组标题靠「编号 + 16px 留白」建立层级，不再靠字重硬撑；纸墨关系——页底 #FAFAF7 暖纸白、文字 #1C1C1A 墨黑、分区仅 1px #E5E4DE 铅笔灰发丝线；密度即美——表格行高 40px、内容 13px、列头 12px 加 0.04em 字距，像书末索引一样密而清晰；字号阶梯收敛为 12→13.5→14→18→24 五档。
- **主角素材**：表格本身与编号目录——数据表就是书页，页眉是「章节号 + 章节名」（如 06 沟通流程）。
- **骨架**：单一壳，左 240px 纸白侧栏 = 全站索引，顶部切换器做成「卷标条」（工作区名 + 页码式计数「5 项 / 9 组」，下拉带各域章节数），主区去卡片化，内容直接排在纸底上靠发丝线分区。
- **胆量花在哪**：全站近乎无彩色（仅一枚墨绿 #1F4E3D 给激活与主按钮）、无阴影、无圆角卡——赌「索引美学」能撑住 B2B 工具的秩序感。
- **form 来自内容的哪里**：9 个配置域本身就是一套销售方法论知识体系（怎么成交、怎么总结、什么算违规），「配置 = 编书」的隐喻在这个题材里是实物不是修辞。
- **token 提案**：#FAFAF7 / #1C1C1A / #6E6E66 / #A8A79E / #E5E4DE / #1F4E3D（墨绿强调）/ #FFFFFF（悬浮面）；radius 4px（近直角）；阴影无，仅 focus 0 0 0 2px；字号阶梯 12/13.5/14/18/24/36；字体栈 "PingFang SC","Source Han Sans SC","Microsoft YaHei" + 等宽数字（"SF Mono",Consolas 兜底）+ tabular-nums。

### C3 · Attio——「灰阶纪律 + 5% 配给制」（现实参照一，注入 Linear 数字规则）

- **逻辑来源**：现实参照。Attio（同领域现代 CRM）拆成可执行规则：accent 每屏累计面积 ≤5%、文字灰阶严格三档、40px 表格行、8px 圆角、描边 6% 以下透明度、分区靠填充色不靠描边。备选注入 Linear 一味药：统计大数字负字距 -0.02em + 几何无衬线气质 + 发丝分割线，让数字更有「仪表」感。
- **借的是什么**：文字三档 #17171C/#6F6F78/#9E9EA6，背景只有 #F7F7F8 与 #FFFFFF 两档；accent 配给制——主色只准出现在激活态、主按钮、链接、选中行左缘线四处；表格行高 40px、内容 13px、表头 12px、悬浮行 #F7F7F8、行分隔线 rgba(23,23,28,.05)；全局 radius 8px（卡）/6px（输入）/4px（tag 近方角）。
- **主角素材**：数据表本身——行 hover、pill 状态、选中左缘线是页面上仅有的「戏」。
- **骨架**：单一壳，左 220px 侧栏，顶部 workspace switcher（工作区图标 + 名 + chevron，浮层带两工作区描述），主区紧凑表格通铺。
- **胆量花在哪**：把「强调」做成配给制——一屏彩色面积 ≤5%，其余全靠灰阶层次，赌用户读出的是「贵」而不是「穷」。
- **form 来自内容的哪里**：40px 行高让「一次沟通」成为可扫读的一行事实——沟通记录这个题材的正确密度就是表格密度。
- **token 提案**：#F7F7F8 / #FFFFFF / #17171C / #6F6F78 / #9E9EA6 / rgba(23,23,28,.06)（线）/ #5B5BD6（紫 accent，或沿用 #436bff）；radius 8/6/4；shadow 0 1px 2px rgba(0,0,0,.04)；字号阶梯 12/13/14/16/22/32；系统栈 + tabular-nums。

### C4 · 飞书——「淡蓝底分区 + 舒服的中文」（现实参照二）

- **逻辑来源**：现实参照。飞书是「中文 + 双模式工作台」的现成同构答案，拆成可执行规则：品牌蓝 #3370FF、有色彩倾向的分区底 #F0F4FF 系（约 30% 页面面积）、卡片靠底色衬托而非描边、激活态 = 浅蓝底 + 蓝字 + 左 3px 蓝条三重编码、中文正文 14px/1.6 的舒适行高。
- **借的是什么**：页面底 #F0F3FA 淡蓝灰承担分区，卡片纯白 borderless + 一档浅阴影；激活态三重编码（底/字/左条）顺手修掉现状可访问性缺陷 8c；顶栏 48px 与侧栏同白，全局搜索常驻顶栏（顺手修掉「无快捷搜索」诊断）；标题 17px/600，表格 13px/1.5。
- **主角素材**：淡蓝底上的白色卡片群——卡片圆角 10px，靠 30% 面积的品牌色调呼吸感分区。
- **骨架**：单一壳 = 顶栏（最左工作区切换器 + 全局搜索 + 头像）+ 224px 侧栏原地换菜单，两模式完全同构；切换器也可放侧栏顶部，二选一但两侧必须一致。
- **胆量花在哪**：分区底色敢用「泛着品牌蓝的蓝灰」而非中性灰——整屏 30% 面积带着品牌温度，这是飞书最被低估的一招。
- **form 来自内容的哪里**：「今日日程/待办/情报中心」放淡蓝底的聚合卡里，蓝 = 中文工作语境里「工作日的清爽」，销售每天打开的情绪基调刚好。
- **token 提案**：#F0F3FA（页底）/ #FFFFFF / #1F2329 / #51565F / #8F959E / #3370FF / #F0F4FF（激活底）/ #E1EAFF（激活描边）；radius 10/8/6；shadow 0 1px 4px rgba(31,35,41,.06)；字号阶梯 12/13/14/17/24/32；系统栈 + tabular-nums。

### C5 · 包豪斯几何——「三原色功能区隔」（秒数轮盘 · 网页分区 #10，还原度 90%，中性派）

- **逻辑来源**：秒数轮盘抽中。Khan Academy 再版那套包豪斯几何语言：三原色红 #E63946 / 黄 #FFB703 / 蓝 #0077B6 + 黑白纯色块、圆/三角/方基本几何单元、栅格对齐、扁平无渐变、几何无衬线（Manrope/Poppins 气质）。
- **借的是什么**：形状即语义——圆 = 状态与人、三角 = 警示（风险/违规）、方 = 内容（卡/表）；三原色各绑一个业务语义且禁止混用（蓝 = 导航与主行动、红 = 风险/违规/删除、黄 = 待办/提醒）；黑白承担 85% 面积，三原色合计 ≤15%；零渐变零模糊阴影。
- **主角素材**：几何图形化的统计卡——今日待办配黄圆、风险数配红三角、沟通数配蓝方，图表用三原色几何编码。
- **骨架**：单一壳，左 216px 白侧栏，顶部「方 + 圆」组合徽标式切换器下拉；侧栏 9 组每组前一枚固定 8px 几何色标（形状轮换、颜色固定语义）。
- **胆量花在哪**：管理后台 9 组菜单变成一眼可记的几何图谱——每组一个形状一个原色，把枯燥的配置树变成视觉记忆装置。
- **form 来自内容的哪里**：违规检测、风险预警天然是「三角警示」的语义宿主——三原色几何在销售风控这个题材里恰好各得其所，不是硬贴的装饰。
- **token 提案**：#FFFFFF / #111111 / #4A4A4A / #F5F5F2（页底）/ #0077B6（蓝）/ #E63946（红）/ #FFB703（黄）；radius 0/4px 方角为主（圆只给状态点）；阴影无（可选 2px 2px 0 rgba(17,17,17,.08) 硬投影仅用于主按钮）；字号阶梯 12/13/14/16/22/34；字体栈 "Manrope","HarmonyOS Sans SC","PingFang SC" + tabular-nums。
- **适配风险（如实标注）**：还原度 90% 但纪律成本最高——三原色一旦脱离语义绑定立即滑向幼儿园风；密集表格页里彩色必须主动退场只留中性。可行，但要求执行自律。

### C6 · 香港街招霓虹（白日转译）——「招牌色块 + 粗黑体」（秒数轮盘 · 东亚分区 #6，还原度 80%，大胆派）

- **逻辑来源**：秒数轮盘抽中，如实标注：夜景霓虹与「浅色生产环境」硬约束直接冲突，做「白日街招」转译——奶白纸底替代深夜墙面、饱和纯色招牌块保留、外发光改为无模糊硬投影、霓虹灯管字改为粗黑体大字。转译后保留约五成基因，还原度按 80% 原始风格计但成品气质已偏「日式 Tories/漫画分格」。
- **借的是什么**：招牌式色块——高饱和纯色（红/黄/蓝/绿）只给「招牌级」元素（页面标题条、状态 tag、空态牌）；所有强调元素 2px #FFF8E7 奶白描边 + 3px 3px 0 无模糊硬投影；标题 900 字重粗黑体直接当招牌字；统计数字 40px 起步、信息密字大。
- **主角素材**：大字标语式页面标题（「今日待办 6 件」像一块挂招）+ 饱和色 tag 群 + 硬投影卡片墙。
- **骨架**：单一壳，左 220px 奶白侧栏（组标题做成小型横招牌），顶部切换器做成「双面招牌」色块下拉。
- **胆量花在哪**：统计卡直接做成街招——黄底黑字大数字 + 硬投影 + 奶白描边，整屏像一面贴满招牌的墙。
- **form 来自内容的哪里**：销售的「喊单/战报」文化——金牌话术、成交案例本来就是贴在墙上的喜报，街招是它们的原生形态。
- **token 提案**：#FBF6EC（奶白底）/ #1A1A1A / #E4322B / #F5B700 / #0B67D0 / #0E9B6C / #FFF8E7（描边奶白）；radius 4px；shadow 3px 3px 0 rgba(26,26,26,.9)（仅招牌级元素）；字号阶梯 12/13.5/14/18/28/44；字体栈 "Source Han Sans SC","PingFang SC"（标题 900 字重）+ tabular-nums。
- **适配风险（如实标注）**：对内部 B2B 明显过猛——彩度与密度一旦失守即廉价促销页感；即便晋级做完整版，生产落地也只建议保留「粗黑体 + 硬投影 + 奶白描边」约两成基因，彩色面积必须压到 10% 以下。

## 四、晋级建议

**三条标准**：单看就够好（独立成立，不依赖成套阐释）；三张彼此骨架气质不同（避免评审时三选一变成三选同一个）；不挤同一外观家族（色彩温度、分区手法、密度哲学至少两维不同）；最多一张用力过头（保留一个冒险名额，但不超过一个）。

**晋级三张：C2、C4、C1**

- **C2（Irma Boom · 九域即九章）**：克制极限的「去卡片化 + 编号索引」骨架，是六张里唯一赌「无彩色秩序」的，单看就足够好且最贴「配置密集型管理后台」的真实主形态——它是生产环境最稳的答案。
- **C4（飞书 · 淡蓝底分区）**：中文工作台的当代常识答案，落地成本最低、用户学习成本为零，骨架「顶栏切换器 + 同构侧栏」与推荐方案咬合最紧；它替三张阵容守住了「大众好感」的基本盘。
- **C1（佐藤可士和 · 一枚徽章）**：能量名额——暖色单色主义 + 徽章符号骨架，与前两张「冷灰纸白」「蓝调分区」完全不挤家族，且符号语言长在产品名上，是唯一有「士气感」叙事的一张，单看即可成立。

三张互补性核验：色彩温度（暖朱红 / 墨绿纸白 / 品牌蓝）三维、分区手法（留白发丝线 / 底色衬托 / 符号重复）三种、密度哲学（索引密 / 舒适中 / 主次分明）三档；无深色侧栏类的大胆手法，最冒险的 C1 也只是「单暖色配给制」，满足「最多一张用力过头」且实际为零超标。

**备选三张保留了什么**：

- **C3（Attio 灰阶纪律）**：气质与 C4 同属冷色低饱和家族，正赛让位；但它的「5% 配给制」与 40px 行高 token 是全场最值得被任何晋级卡吸收的基因，作为融合素材保留。
- **C5（包豪斯几何）**：骨架成立但纪律成本高，且「几何色标图谱」与 C1 的「符号重复」思路同源；它的「形状即语义」可降级注入任何晋级卡的空态、图表与风险标识，作为语义层素材保留。
- **C6（街招白日版）**：按标准属于「用力过头」，不晋级生产方向；保留「粗黑体 + 硬投影」两成基因，供营销物料、成交战报页等非生产场景取用。
