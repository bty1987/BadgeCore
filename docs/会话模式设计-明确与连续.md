# 会话模式设计：明确会话 vs 连续累积（按角色场景优化）

> 版本 v0.1｜2026-09-13｜状态：待拍板（默认参数待确认）
> 背景：当前链路把设备 VAD 断句（唤醒→说话→静音）当作一次「沟通」，对销售场景合理；对前台等模糊连续场景会产生记录碎片化、分析成本爆炸、业务边界失真三重问题。

---

## 1. 问题分析

| 场景 | 对话特征 | 现状模型的缺陷 |
|---|---|---|
| 销售/顾问（明确模式） | 每次接待有清晰起止 | ✅ 现状即合理：一次接待=一条记录=一份报告 |
| 前台/接待（连续场景） | 全天零散说话，边界模糊 | ①一天几十条碎片记录 ②每次静音断句触发一次 LLM 分析（30-50 次/天）③访客接待横跨/粘连多个 VAD 会话，业务边界失真 |
| 会议随行/巡检（衍生） | 长时间连续 | 同前台，且更需手动控制收口 |

**根因**：会话边界由设备 VAD 定义，而业务边界应由场景策略定义。解法=**采集与收口解耦**。

## 2. 设计：工作会话缓冲 + 场景化收口策略

```
板子每次开口（VAD 会话，固件零改动）
  → 文本实时追加「工作会话缓冲」（[HH:MM] 时间前缀；即时落盘防丢）
  → 录音照常分片落盘
  → 规则告警（竞品/风险词）即时执行
收口时机（按模式）：
  明确模式：静音即收口（现状）
  累积模式：静音>N分钟(默认10) 软分段 ＋ 每日定时(默认18:00) ＋ 后台手动收口
  手动模式：仅手动
收口动作：拼接完整文本 → 生成一条聚合记录 → 一次 LLM 分析 → 可选合并音频跑说话人分离
```

### 模式参数（后台设置页可配）

| 参数 | 默认 | 说明 |
|---|---|---|
| session_mode | explicit | explicit / continuous / manual |
| gap_close_minutes | 10 | 累积模式：静音超此时长做软分段标记（不终结当日缓冲） |
| daily_close_time | 18:00 | 累积模式：每日自动收口时刻 |
| 聚合记录命名 | 自动 | 「09-13 前台接待记录（09:12-17:45，23 段）」 |

### 成本/效果对比（前台场景）

| | 现状（每 VAD 会话收口） | 累积模式 |
|---|---|---|
| 记录数/天 | 30-50 条碎片 | 1-3 条聚合 |
| LLM 分析/天 | 30-50 次 | 1-3 次 |
| 讯飞分离/天 | 每会话一次 | 每收口一次（合并音频） |
| 日报可用性 | 差（碎片无上下文） | 好（全天上下文） |
| 实时告警 | ✅ | ✅（逐段即时，不受收口影响） |

## 6. 硬件功耗与「驻留」分析（2026-09-13 补）

**先拆概念**：「长时间驻留」有两层，结论不同——
- **待机常驻**（在线+唤醒词待命）：小智天生就是这种模式，**插电即可无限驻留**，不存在不支持；
- **长时间连续录音/推流**：这才是耗电场景，但**累积模式恰恰不需要它**——设备行为不变（仍是一次次短 VAD 会话），聚合在服务端完成。「连续场景」≠「设备连续推流」。

**电量现实账**（1.75C，锂电池 + AXP2101 类电源管理）：
- 耗电大户排序：AMOLED 亮屏（700nit）>> WiFi 推流 >> 唤醒词待机
- 估算：亮屏连续使用 2-4h；待机+间歇对话约半天；熄屏/调暗显著延长（精确值待实测，PRD「录音 12h/待机 5 天」本就是量产墨水屏硬件的指标，开发板阶段不背）

**场景-供电匹配（关键）**：
- 前台（累积模式目标场景）：**固定岗位=插电常驻**，电量自解；屏幕常显还可兼做身份牌/状态牌
- 销售（明确模式）：移动+见客户才开+随用随充；「移动」与「常开」两个需求本就不同时出现

**固件层省电（Fork 后实施，社区已有 1.75 系先例）**：
- 三级省电：背光超时熄灭/调暗至 20%（最大耗电项）→ 电源管理模式 → PMIC 真关机
- 电量上报后台（设备健康 ALL-604）+ 低电量告警
- IMU 抬手亮屏（板载六轴，兼顾隐私与功耗）

**架构结论**：累积模式不改变设备侧行为 → 不引入新的驻留/功耗要求 → 电量问题由「场景-供电匹配 + 固件省电」解决，**不阻塞会话模式实施**。
